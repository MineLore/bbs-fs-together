# BBS FS Together

[BBS FS](https://github.com/Wemppy4/bbs-fs) (ветка `1.21.11`) с мультиплеерными функциями
[BBS Together](https://modrinth.com/mod/bbs-together) (ChillinWithDylan, MIT).

Оригинальный BBS Together — это **не аддон**, а полная копия старого BBS 1.7.7 (mod id `bbs`)
под Minecraft 1.20.4, исходники не опубликованы. Его изменения восстановлены сравнением
декомпилированных jar BBS 1.7.7 и BBS Together 1.3, и **переписаны** под BBS FS 1.21.11 —
не перенесены строка в строку: у FS другой интерфейс, сетевой API 1.21 (payload'ы), стабильные
id реплеев и шина `FilmEditEvents`.

Mod id остаётся `bbs`, так что аддоны BBS FS (IRLights и т.д.) работают как прежде.

## Что работает

| Функция | Как сделано |
|---|---|
| **Живое совместное редактирование фильма** | Каждая завершённая правка (включая undo/redo) берётся из `FilmEditEvents` и рассылается через сервер всем, у кого открыт тот же фильм. Получатель применяет её через `fromData` — эха нет. |
| **Синхронизация при сохранении** | Сохранение фильма рассылается остальным редакторам как проверка согласованности; применяется, только если получатель 3 с ничего не правил (иначе затёрло бы его ещё не отправленные правки). |
| **Изменения списка фильмов** | Создание / удаление / переименование фильмов и папок сразу видно у всех. |
| **Присутствие и цвет игрока** | Кто какой фильм и реплей открыл; цвет — `primary color` из настроек BBS. |
| **Головы игроков** | В списке фильмов и в списке реплеев — у кого что открыто. |
| **Курсоры других игроков** | На таймлайне камеры и в dope sheet реплея, с подсветкой их выделения (клипы / ключевые кадры) и подписью ника. |
| **Блокировка формы** | Пока один игрок выбирает форму реплея, второй не может открыть палитру формы того же реплея. |
| **`/bbs record <игроки>`** | Все выбранные игроки начинают запись своего выбранного реплея одновременно; повторная команда останавливает. Сама команда вырезается из записанных действий. |
| **Синхронизация ассетов** | При входе сервер присылает список файлов `config/bbs/assets` с SHA-1; клиент докачивает недостающие/изменённые. Опционально — раздача своих файлов другим игрокам. |
| **Скрытие других редакторов** | В редакторе фильма игроки, которые тоже в редакторе (летают камерой), не рендерятся. |
| **Предупреждение в HUD** | «N игроков в редакторе фильмов» — плейбек в редакторе меняет мир. |
| **LAN** | Хост открытого в LAN мира работает с фильмами через сеть, как все остальные. |
| **Исправление FS** | Сборка чанков пакетов на сервере теперь своя для каждого игрока — раньше одновременные отправки двух игроков могли перемешаться. |

## Настройки (BBS → Together)

| Ключ | По умолчанию | |
|---|---|---|
| `cursors` | вкл | показывать курсоры других |
| `heads` | вкл | показывать головы в списках |
| `asset_download` | вкл | качать ассеты с сервера при входе |
| `asset_upload` | **выкл** | раздавать свои локальные ассеты другим |
| `asset_receive` | **выкл** | принимать ассеты, присланные другими игроками |

Отличие от Together: там раздача своих файлов была включена по умолчанию, а сервер рассылал
их всем подряд. Здесь сервер пересылает только тем, у кого включён `asset_receive`, и только от
игроков с правом на панели BBS.

## Что сознательно не перенесено

- **Объединение записей через «мастер»-клиента** — с живой ретрансляцией не нужно: каждый
  применяет свой дубль к своему реплею, и эта правка расходится остальным.
- **Запрет открывать редактор фильмов без OP на клиенте** — права и так проверяются на сервере
  (`PermissionUtils.arePanelsAllowed`, gamerule `bbs_editing`).
- **Пере-синхронизация по индексам реплеев** (`pendingSwap`) — в FS у реплеев стабильные id.

## Устройство

Весь код Together — в двух классах, правки в самом FS точечные (~170 строк), чтобы
подтягивать обновления апстрима без конфликтов:

- `src/main/java/mchorse/bbs_mod/network/together/TogetherServer.java` — реестр присутствия,
  ретрансляция, блокировки, `/bbs record`, раздача ассетов.
- `src/client/java/mchorse/bbs_mod/network/together/TogetherClient.java` — всё клиентское.

Пакеты имеют свои id (`bbs:tc1..9`, `bbs:ts1..6`) — у FS `c18–c20`/`s14–s16` уже заняты.

## Сборка

Нужен JDK 21.

```
JAVA_HOME=<jdk-21> ./gradlew remapJar
# -> build/libs/bbs-2.7-together.1-1.21.11.jar
```

## Обновление из апстрима

```
git fetch origin
git rebase origin/1.21.11   # конфликты возможны только в точках подключения
```
